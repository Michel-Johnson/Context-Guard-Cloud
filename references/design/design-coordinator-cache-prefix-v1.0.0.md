# Coordinator 稳定前缀与逐轮状态

文档版本：v1.0.0。

本次范围是模型请求组装，不改变 Map 格式、授权、版本事务或派发行为，不提供模型服务器上的 KV fork。适用于同项目、同角色和同许可工具集的对话接续；实验分支的完整 fork API 不在本次范围内。

## 请求布局

固定工具 JSON Schema + system（角色、固定渠道呈现规则、项目记忆、节点导航），随后是原生历史及新输入。Main 全局版本、事项状态、当前焦点记忆和输出渠道保存在每条已接受输入的私有 `serverContext`，发送时放在该输入前，不嵌进 system。原始输入正文与公共 UI 展示保持不变。

`buildCoordinatorContext` 返回格式 2：`staticText`、按实际内容生成的 `staticVersion`、`dynamicText`、Main `version`；保留合成 `text` 供旧调用方读取。稳定版本不依赖全局 Main 版本，但项目记忆、导航或授权范围变化仍会改变稳定前缀，不能以缓存为由复用失效事实。

## 复用与权限

`coordinatorPrefix` 按角色、已过滤的项目上下文及许可工具定义做内容哈希，复用不可变 system/tools。进程内缓存最多 32 项、8 MiB，重启后重建；它不是供应商的 KV 缓存，不省去每次 API 的文本传输。

工具定义在同许可配置内不随 Slack/Web 或 fork 身份变动。来源专用的 `react_to_user`、`show_model_menu` 仍在执行层检查真实服务端来源和操作者，非 Slack 或伪造身份得到 `TOOL_FORBIDDEN`；项目、角色、文件写入等原有授权配置继续约束传入服务的工具集合。不能仅靠 system 或“分身说明”限制写入。

## 历史、接续与兼容

新状态只在接受输入时追加，不使用下一轮的快照重建过去的输入。重试复用当时已接受的上下文；新的正常输入重新读取 Main。现有 `continueIn` 复制已完成原生历史及压缩检查点，首条子输入可附短角色说明，不调用供应商、不改 system 或工具目录。

压缩仍仅产生带原文哈希的历史视图，不删除原文、不拆工具调用与结果，不压缩静态前缀。旧的 `{version,text}` 上下文和无 `serverContext` 的历史兼容读取，不猜测拆分旧字符串。已有图片/文档摘要、跨供应商私有块投影仍按原有策略运行；这些投影与摘要替换可能有意改变请求历史，因此不能宣称所有多模态请求绝对只追加。

## 观测与验收

私有模型轮次指标增加 system、tools、envelope、history 哈希和消息数，并同时保存输入 tokens、cached tokens、首字及完成耗时。未知缓存用量保持 null，不当作零；兼容 Anthropic 的 cache_read_input_tokens 与 OpenAI 的 prompt_tokens_details.cached_tokens。公共对话不返回这些诊断，不写提示词或凭据到指标。

离线回归验证内容更新、权限隔离、旧格式、重试、接续、原生私有块/回执及压缩。真实供应商实验在独立进程直接调用模型，不能替代网页/Slack 端到端或部署验收。缓存仍由供应商按实际前缀和资源状态决定；本设计消除可控的前缀变动，不承诺 100% 命中。
